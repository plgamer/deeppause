# DeepPause

*English: see `README.md` in this extension.*

一个 VS Code 面板，用来回放一段**模拟的**编码 agent 会话：流式输出的思考过程、
工具调用、待办清单、diff，以及一次先失败后通过的测试运行。

任务是开放式运行的 —— 节拍会一直产生，直到你手动打断它。

这只是个玩具。**它不调用任何 AI 服务，不向任何地方发送数据，也不会修改你的任何
文件。** 你看到的一切都是本地生成的：一个短语库，加上你当前工作区里已有的内容。

> **与任何 AI 公司或产品均无关联、未获其背书、也不存在任何联系。**
> DeepPause 是一个独立的原创项目，不包含任何第三方代码、素材、logo 或商标。

## 安装

用打包好的 `.vsix`：

```
code --install-extension deeppause-0.2.1.vsix
```

或者在 VS Code 里：**扩展** → `…` 菜单 → **从 VSIX 安装…**，然后重新加载窗口。

## 打开会话

点击活动栏（最左侧那一条）里的 **DeepPause** 图标，侧边栏会直接进入一个正在运行的
会话 —— 不需要输入任何命令。

其他入口：

| | |
| --- | --- |
| `Ctrl/Cmd+Alt+K` | 聚焦侧边栏里的会话 |
| **DeepPause: Open Session** | 同上，从命令面板触发 |
| **DeepPause: Open Session in Editor** | 在编辑器标签页里开一个全宽的会话 —— 也就是视图标题栏上的 ⧉ 按钮 |

侧边栏和编辑器标签页是两个相互独立的会话，可以同时跑。

## 使用

- 在输入框里写一个任务，按 **Enter**。它会一直运行，直到你停止它。
- **Esc** 打断当前这一轮。（视图标题栏上的 ■ 按钮效果相同，并且会停掉所有正在
  运行的会话。）
- **Ctrl/Cmd+Shift+Backspace** 是「panic」：打断一切、关掉编辑器标签页、收起侧边栏。
- `/help` 列出命令，`/clear` 清空当前记录。

状态栏里模型旁边的 **run** 选择器，可以把一轮的时长限制在 1 分钟到 1 小时之间，
而不是无限运行。预算用完时，这一轮会以一段总结收尾，而不是说到一半突然停住。
冻结期间的时间不计入预算。

当 VS Code 窗口失去焦点时，会话会自动冻结。

## 配置项

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| `deeppause.agentName` | `DeepPause` | 横幅和标签页标题里显示的名字 |
| `deeppause.models` | `["orion-4.5", …]` | 模型选择器里的条目（纯装饰） |
| `deeppause.speed` | `1` | 回放速度倍数 |
| `deeppause.useWorkspaceFiles` | `true` | 从打开的工作区中取真实的路径和符号名 |
| `deeppause.accent` | `#7dd3a0` | 强调色 |

## 实现原理

| 文件 | 职责 |
| --- | --- |
| `src/scan.ts` | 扫描工作区，取出真实的文件路径、符号名和代码片段 |
| `src/corpus.ts` | 带 `{file}` / `{sym}` 占位符的短语库 |
| `src/engine.ts` | 节拍调度器 —— 以带抖动、偶尔卡顿的时序发出事件 |
| `src/session.ts` | 绑定到一个 webview 的会话，以及共用的 HTML |
| `src/view.ts` | 活动栏宿主 |
| `src/panel.ts` | 编辑器标签页宿主 |
| `media/main.js` | 把事件渲染成对话记录 |

一次开放式运行会在一个带权重的节拍池里循环 —— 思考、读取、grep、编辑、测试、
说话 —— 推进一份滚动的待办清单，并在 token 计数爬得够高时伪造一次上下文压缩，
这样状态栏就不会一直卡在下限。记录只保留最近 400 个块。

时序模型比措辞更重要。输出以 22–77 ms 一个词的节奏流式推进，并有约 3.5% 的概率
停顿 0.5–1.8 秒 —— 因为节奏均匀的文字读起来像打字机效果，而不像一个模型。

## 开发

```
npm install
npm run compile
```

按 `F5` 启动扩展开发宿主（Extension Development Host）—— 这是用来开发 DeepPause
本身的，不是日常使用它的方式。`npm run watch` 会在保存时自动重新编译。

打包：`npx @vscode/vsce package`。
